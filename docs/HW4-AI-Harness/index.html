AI Harness System Design

AI Paper Reading and Presentation Assistant

1. Project Overview

This project designs a mock AI harness that helps a student read a technical research paper and prepare a presentation. The system accepts a paper PDF and presentation preferences, then produces a structured summary, concept explanations, slide outline, speaking script plan, and presentation readiness evaluation.

The focus is system design, not model training. The current implementation is a local mock prototype that demonstrates tool calling and orchestration without real external APIs.

2. Problem Definition

Technical papers are difficult to present because students must identify the problem, method, evidence, limitations, and key concepts from dense text. A single chatbot response can be useful, but it may lose paper structure or produce unsupported claims.

The design goal is to make the process inspectable: preserve intermediate artifacts, call specialized tools, store useful context, and evaluate the final presentation package before returning it.

3. AI Harness Architecture

The LLM acts as the controller. It plans the task, routes function calls to tools, stores intermediate results in memory, and uses an evaluation module to decide whether the output is ready or needs revision.

4. Tool Design

Each tool has a narrow responsibility, structured inputs, and structured outputs. This makes the harness easier to test and easier to debug.

Tool Input Output When Called
parse_paper_pdf PDF path or uploaded file Metadata, sections, key concepts First step after paper upload
summarize_section Section title and text Section summary and key points After paper sections are available
explain_concept Concept and audience level Audience-aware explanation After key terms are extracted
generate_slide_outline Paper summary and talk length Slide titles, bullets, timing After summaries are complete
evaluate_presentation_readiness Outline and rubric Score, checks, recommendations Before final output is returned

5. Agent Workflow

The workflow begins with user input and ends with a presentation-ready package. The evaluation step can trigger revision if an output is incomplete or unclear. 

flowchart TD
    start["User uploads paper"]
    prefs["User provides preferences<br/>audience level, talk length, goal"]
    plan["LLM plans tasks"]
    parse["PDF parser extracts structure"]
    summary["Section summarizer summarizes"]
    concepts["Concept explainer explains terms"]
    outline["Slide outline generator creates outline"]
    eval["Evaluation tool checks readiness"]
    decision{"Ready?"}
    revise["Revise weak part"]
    final["Final report is generated"]

    start --> prefs
    prefs --> plan
    plan --> parse
    parse --> summary
    summary --> concepts
    concepts --> outline
    outline --> eval
    eval --> decision
    decision -- "Yes" --> final
    decision -- "No" --> revise
    revise --> eval

6. Orchestration Logic

The controller keeps a memory dictionary with the user request, parsed paper, section summaries, concept explanations, slide outline, evaluation result, and tool-call trace. This represents how an LLM-based harness can pass outputs from one tool into the next.

  • If no parsed paper exists, call parse_paper_pdf.
  • If sections exist but summaries are missing, call summarize_section.
  • If key concepts exist, call explain_concept.
  • If summaries are complete, call generate_slide_outline.
  • If an outline exists, call evaluate_presentation_readiness.

7. Evaluation Method

The readiness evaluator checks whether the generated outline is usable for a presentation. The mock rubric rewards coverage, clarity, timing, and a final takeaway slide.

Metric Purpose Mock Weight
Coverage Motivation, architecture, and results are represented. 30
Clarity Each slide has enough concrete bullet points. 25
Timing Total outline time fits the requested talk length. 20
Takeaway The presentation closes with a clear final message. 25
